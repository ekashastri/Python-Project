# Optical Character Recognition (OCR) Preprocessing & Extraction Pipeline

This document describes the image verification, format validation, upscaling, preprocessing pipelines, caching mechanisms, page segmentation logic, and quality-scoring heuristics used by Ekora's OCR system.

---

## 1. Input Image Verification & Format Validation

Before executing any OCR processing, the system performs validation checks to eliminate channel-order regressions and avoid sending blank or unreadable regions to Tesseract:

### Format & Channel Normalization
The input image is validated and standardized to a BGR image:
- **Grayscale**: Converted to BGR (`cv2.COLOR_GRAY2BGR`).
- **BGR**: Checked and cloned to prevent memory leaks.
- **BGRA**: Converted to BGR to strip the alpha channel (`cv2.COLOR_BGRA2BGR`).

### Region Content Pre-checks
- **Dimension Check**: The crop selection width and height must be at least 4 pixels.
- **Contrast Check**: Computes the standard deviation of grayscale pixel intensities. A standard deviation $< 2.0$ indicates a blank canvas or lack of contrast, prompting early rejection.
- **Non-Background Check**: Converts the image to binary based on background brightness (light/dark) and counts active foreground pixels. If fewer than 5 active pixels exist, the crop is classified as empty and ignored.

---

## 2. Dynamic DPI Scaling

Small text crops (e.g. single-character drawings or tiny diagram labels) suffer from low resolution, which degrades Tesseract's accuracy. Ekora resolves this by dynamically upscaling small images:

- If `height < 100` or `width < 150`, a scale factor is calculated:
  $$\text{scale\_factor} = \max\left(2.0, \frac{150.0}{\text{width}}, \frac{100.0}{\text{height}}\right)$$
- The image is resized using cubic interpolation (`cv2.INTER_CUBIC`), and the configuration string specifies `--dpi 300` to indicate high resolution.

---

## 3. Dynamic Preprocessing Pipelines

Ekora evaluates multiple image variants (candidates) to find the one that yields the best recognition quality:

| Pipeline Name | Description | Binarization / Enhancement | Background Inversion |
| :--- | :--- | :--- | :--- |
| **Baseline** | Default RGB representation | Direct conversion to RGB | None (default Tesseract) |
| **Grayscale** | Grayscale intensity | OpenCV grayscale conversion | None |
| **Otsu** | Binarized Otsu threshold | Otsu's thresholding | Inverted if canvas is dark |
| **Adaptive** | Adaptive local binarization | Gaussian adaptive thresholding | Inverted if canvas is dark |
| **CLAHE** | Histogram equalization | CLAHE followed by Otsu | Inverted if canvas is dark |

### Conditional Deskewing
A deskew rotation is calculated on active pixels using `cv2.minAreaRect`. Rotation is only applied if the detected angle indicates a significant skew ($1.5^\circ < |\theta| < 43.5^\circ$) to avoid introducing interpolation blur onto unskewed paths.

---

## 4. Prioritizing Cache & Limiting Combinations

To maintain real-time desktop responsiveness, Ekora optimizes execution pathways:

- **Baseline Priority**: The original BGR-to-RGB converted image (representing the baseline) is always executed first.
- **Pipeline Caching**: The class-level variable `_last_successful_pipeline` caches the name of the last preprocessor that yielded high confidence. The cached preprocessor is scheduled to run immediately after the baseline.
- **Early Exit**: If any pipeline meets the confidence threshold (default $60.0$), execution immediately returns without running remaining fallbacks.
- **High-Value PSMs**: Instead of testing every Page Segmentation Mode, the system uses the aspect ratio to schedule only one PSM:
  - **Single Line Label**: If `height < 55` or `aspect > 4.5`, the system runs `PSM 7` (Single line).
  - **Auto**: Otherwise, it runs `PSM 3` (Fully automatic page segmentation).

---

## 5. Text Quality Heuristic Scoring

Instead of relying solely on raw OCR confidence, Ekora scores candidate text outputs using multiple quality metrics:

$$\text{Score} = \text{Confidence} + \text{Alnum\_Ratio} \times 20.0 - \text{Suspicious\_Ratio} \times 50.0 + \min(\text{Alnum\_Count}, 30) \times 1.5$$

- **Alnum Ratio**: Ratio of alphanumeric characters to total output length. High ratios increase the score.
- **Suspicious Ratio**: Ratio of noisy characters (e.g. `|`, `~`, `^`, `\`, `°`) typically generated by margins or background artifacts. Higher ratios penalize the score.
- **Alnum Count**: Rewards longer, coherent words/phrases over single-character noise.

If a pipeline score exceeds the best score, it becomes the active candidate. If all pipeline combinations yield a score of $-999.0$ (no characters found), the system reports "No text found in selected region."

---

## 6. Diagnostic Logging & Coordinates Offset

- **OCR_DEBUG Flag**: Toggles verbose stdout output of image metadata, active schedules, individual runs, and output quality scores.
- **Coordinate Offsets**:
  $$x_{\text{placed\_doc}} = \frac{x_{\text{crop\_start}} + x_{\text{offset\_screen}} - \text{pan\_x}}{\text{zoom}}$$
  $$y_{\text{placed\_doc}} = \frac{y_{\text{crop\_start}} + y_{\text{offset\_screen}} + 25 - \text{pan\_y}}{\text{zoom}}$$
  The recognized text is aligned and placed as an editable vector `text` shape on the canvas layer.
